# Оптимизации ESP8266 проекта

## Применённые оптимизации

### 1. Управление памятью
- **Удалены STL контейнеры**: Заменены `std::vector` и `std::map` на собственные структуры
- **Кольцевой буфер**: Вместо динамического вектора используется фиксированный кольцевой буфер
- **Компактные структуры**: `char[8]` заменён на `uint16_t` для номеров записей
- **Ограниченный кэш**: Кэш файлов ограничен 6 элементами

### 2. Веб-сервер
- **Chunked Transfer**: Большие ответы отправляются порциями по 10 записей
- **Предварительное выделение памяти**: `String.reserve()` для буферов
- **Статические буферы**: Фиксированные размеры буферов для snprintf

### 3. Файловые операции
- **Асинхронная запись**: Файл обновляется раз в 5 секунд, а не при каждом изменении
- **Батчевая запись**: Накопление изменений в буфере перед записью
- **Кэширование**: Статические файлы загружаются в память один раз

### 4. Таймеры и прерывания
- **Ticker оптимизация**: Используется стандартный Ticker с интервалом 0.01с (10ms)
- **Оптимизированный debounce**: Использует битовые операции
- **Точный отсчёт времени**: Интервал 10ms для сотых долей секунды

**Примечание**: Hardware timer был заменён обратно на Ticker из-за проблем с настройкой частоты.

### 5. Компиляция
- **Оптимизация по размеру**: `-Os` флаг
- **Удаление неиспользуемого кода**: `-ffunction-sections`, `-Wl,--gc-sections`
- **LWIP Low Memory**: Экономия RAM в сетевом стеке
- **VTables в Flash**: Перенос таблиц виртуальных функций во Flash

## Результаты оптимизации

### Экономия RAM:
- Удаление STL: ~2-4KB
- Кольцевой буфер: ~1-2KB  
- Компактные структуры: ~50% на каждую запись
- Ограниченный кэш: ~1-3KB

### Экономия Flash:
- Удаление STL: ~10-15KB
- Оптимизация компилятора: ~5-10KB

### Производительность:
- Ticker с точным интервалом: стабильный отсчёт времени
- Chunked transfer: отзывчивость веб-интерфейса
- Асинхронная запись: меньше блокировок

## Мониторинг

Добавлена функция `printMemoryStats()` для отслеживания:
- Свободная память (heap)
- Максимальный свободный блок
- Фрагментация памяти

Статистика выводится каждые 30 секунд в Serial.

## Рекомендации по использованию

1. **Мониторинг памяти**: Следите за выводом статистики в Serial
2. **Размер записей**: При приближении к лимиту 512 записей рассмотрите архивирование
3. **Кэш файлов**: При добавлении новых статических файлов увеличьте размер кэша
4. **Веб-интерфейс**: При медленной работе уменьшите CHUNK_SIZE в обработчиках
