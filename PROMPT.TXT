==================================================
ЗАДАЧА
==================================================

Проект представляет собой спортивный таймер.

ESP8266:
- получает команды через кнопки;
- формирует отсечки времени;
- хранит отсечки в mainArray;
- предоставляет WEB-интерфейс;
- проект уже полностью работоспособен.

Необходимо добавить передачу новых или измененных отсечек на внешний компьютер по UDP.

Архитектура должна быть следующей:

ESP8266 = UDP-сервер
Python receiver.py = UDP-клиент

ESP8266 должен принимать запросы от receiver.py и отвечать на них.

==================================================
ЧАСТЬ 1. UDP-СЕРВЕР ESP8266
==================================================

Добавить UDP-сервер на порт:

1080

Порт должен быть выделен в отдельную константу.

receiver.py периодически отправляет на ESP8266 текстовую строку:

ASK

При получении ASK ESP8266 должен:

1. Найти в mainArray первую запись, у которой:

sync == false

2. Если такая запись найдена, передать receiver.py одну текстовую строку с тремя полями, разделенными запятыми:

<порядковый_номер>,<num>,<shot>

Например:

15,237,01:23:45

Где:

- первое поле — фактический порядковый номер записи в mainArray;
- второе поле — поле num, число от 0 до 999;
- третье поле — поле shot, содержащее время в формате:
  HH:MM:SS

Использовать фактические типы и названия полей из существующего проекта.

3. После отправки данных ESP8266 должен ожидать подтверждение от receiver.py:

OK

4. Если OK получен в течение 100 мс:

- установить для отправленной записи:

sync = true

- завершить обработку текущего запроса;
- не отправлять следующую запись в рамках этого же запроса.

Следующая запись должна быть передана только при следующем запросе ASK.

5. Если OK не получен в течение 100 мс:

- считать передачу неуспешной;
- НЕ изменять sync;
- завершить обработку;
- при следующем ASK попытаться передать эту же запись снова.

6. Если при обработке ASK не найдено ни одной записи:

sync == false

ответить:

NONE

После этого завершить обработку запроса.

==================================================
ВАЖНЫЕ ТРЕБОВАНИЯ К ESP8266
==================================================

Работа UDP-сервера не должна нарушать работу спортивного таймера.

Особенно важно:

- не блокировать loop();
- не использовать длительные delay();
- не ждать UDP-ответ синхронно длительное время;
- таймаут ожидания OK — максимум 100 мс;
- обработка UDP должна иметь минимальный приоритет относительно основной логики таймера;
- основная работа таймера, кнопок и WEB-интерфейса должна продолжаться нормально.

Предпочтительно реализовать UDP-обработку как неблокирующую state machine, вызываемую из loop(), если это соответствует архитектуре существующего проекта.

Не создавать отдельный поток/RTOS-задачу, если это не требуется существующей архитектурой ESP8266.

Нужно учитывать, что receiver может повторно отправить ASK после таймаута.

==================================================
ЧАСТЬ 2. PYTHON RECEIVER
==================================================

Создать отдельное приложение:

receiver.py

Оно работает на NixOS Linux.

receiver.py является UDP-клиентом.

ESP8266 является UDP-сервером.

IP ESP8266:

192.168.4.1

UDP-порт:

1080

IP и порт обязательно вынести в константы в начале программы:

ESP_IP = "192.168.4.1"
ESP_PORT = 1080

Также таймаут выделить в отдельную константу:

UDP_TIMEOUT = 0.1

192.168.4.1:1080

строку:

ASK

4. Ждать ответ максимум 100 мс.

==================================================
ОБРАБОТКА ОТВЕТА
==================================================

Возможны два основных варианта ответа.

Вариант 1:

NONE

Это означает, что новых несинхронизированных записей нет.

В этом случае ничего не записывать в файл и перейти к следующему циклу опроса.

Вариант 2:

<index>,<num>,<shot>

Например:

15,237,01:23:45

Где:

index = 15
num = 237
shot = 01:23:45

После получения такой строки:

1. Проверить корректность формата.
2. Записать полученные данные в текстовый файл.
3. После успешной записи отправить ESP8266 подтверждение:

OK

Подтверждение OK означает:

"Данные успешно приняты receiver.py".

Только после этого ESP8266 имеет право установить:

sync = true

для соответствующей записи.

Это обеспечивает повторную передачу записи при следующем ASK.
